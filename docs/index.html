01 · O desafio

Consistência sem acoplamento

Reservar um ingresso envolve disponibilidade, confirmação, emissão e notificação. Executar tudo dentro da requisição HTTP torna a experiência frágil e difícil de recuperar.

01

Resposta rápida

A API registra a intenção e devolve `202 Accepted`, sem aguardar toda a cadeia operacional.

02

Entrega confiável

Outbox, publisher confirms e ACK depois do commit reduzem janelas de perda.

03

Falha visível

Retry com atraso e DLQ separam erro transitório de intervenção operacional.

02 · Componentes

Arquitetura orientada a mensagens

Cada processo tem uma responsabilidade clara. As camadas Domain e Application permanecem independentes de HTTP, EF Core, Hangfire e RabbitMQ.

04 · Engenharia

Decisões que o código demonstra

O case foi mantido pequeno o suficiente para leitura, mas preserva os pontos que realmente importam em sistemas distribuídos.

Domínio explícito

Pending, Confirmed, TicketIssued, Notified, Rejected, Expired e Cancelled possuem transições protegidas.

Concorrência

Version é um concurrency token; duas mensagens não podem reservar os mesmos assentos silenciosamente.

Observabilidade

CorrelationId acompanha a cadeia e JobExecutions registra resultado, tentativa e detalhe.

Segurança do case

Domínio, dados e infraestrutura são fictícios. Credenciais são apenas defaults locais do Docker Compose.
